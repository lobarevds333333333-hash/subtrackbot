# SubTrackBot — Telegram-бот для отслеживания подписок

Бот помогает не пропускать продление платных подписок (Netflix, Spotify,
YouTube Premium и любых других): вы вносите дату окончания, а бот раз в сутки
проверяет сроки и присылает напоминание за 3 дня до списания.

🎥 Демо-скринкаст: [screencast.mp4](screencast.mp4) (19 сек, весь цикл:
добавление подписки → список → напоминание за 3 дня → удаление).

## Возможности

| Команда | Что делает |
|---|---|
| `/start` | Приветствие и краткая инструкция |
| `/add` | Диалог добавления подписки: название сервиса → дата окончания `ДД.ММ.ГГГГ` |
| `/my_subs` | Список подписок с остатком дней |
| `/remove` | Выбор подписки кнопками и удаление |
| `/cancel` | Отмена текущего диалога |

Напоминание за 3 дня: «Ваша подписка на Netflix закончится через 3 дня!»

## Быстрый старт

1. Нужен Python 3.10+.

2. Создайте и активируйте виртуальное окружение:

   ```bash
   python -m venv .venv
   source .venv/Scripts/activate    # Git Bash / терминал VS Code
   .venv\Scripts\activate           # cmd
   .venv\Scripts\Activate.ps1       # PowerShell
   ```

3. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

4. Получите токен у [@BotFather](https://t.me/BotFather) (`/newbot`).

5. Задайте токен в переменную окружения `BOT_TOKEN`:

   ```bash
   export BOT_TOKEN="1234567890:AA..."        # Git Bash
   set BOT_TOKEN=1234567890:AA...             # cmd
   $env:BOT_TOKEN="1234567890:AA..."          # PowerShell
   ```

6. Запустите бота:

   ```bash
   python bot.py
   ```

## Как проверить напоминание прямо сейчас

1. Запустите бота и добавьте подписку `/add` с датой окончания
   «сегодня + 3 дня» (например, 10.11.2026, если сегодня 07.11.2026).
2. Задача `daily_sub_check` выполняется через 10 секунд после старта бота
   и затем раз в 24 часа — напоминание придёт в течение первых 10 секунд.
3. Повторного напоминания в тот же день не будет: в базе ставится флаг
   `reminded`. При повторном добавлении того же сервиса через `/add` дата
   обновляется, флаг сбрасывается.

## Как это устроено

```
subtrackbot/
├── bot.py             # команды, диалог /add, JobQueue, обработка ошибок
├── db.py              # слой SQLite (создание таблицы, CRUD)
├── requirements.txt
├── README.md
└── subscriptions.db   # создаётся автоматически при первом запуске
```

Хранение — локальная SQLite-таблица:

```sql
CREATE TABLE subscriptions (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id      INTEGER NOT NULL,
    service_name TEXT    NOT NULL,
    end_date     TEXT    NOT NULL,          -- ISO 'ГГГГ-ММ-ДД'
    reminded     INTEGER NOT NULL DEFAULT 0
);
```

По сравнению с минимальной схемой из ТЗ (`user_id, service_name, end_date`)
добавлены два служебных поля: `id` — чтобы в `/remove` удалять конкретную
запись, и `reminded` — чтобы напоминание не приходило дважды за день
(например, после перезапуска бота, когда задача срабатывает с `first=10`).

## Настройка

- `REMIND_DAYS` в `bot.py` — за сколько дней предупреждать (по умолчанию 3).
- График проверки настраивается в `main()`:

  ```python
  job_queue.run_repeating(check_subscriptions, interval=timedelta(days=1), first=10)
  # или в фиксированное время:
  job_queue.run_daily(check_subscriptions, time=time(hour=3, minute=0))
  ```

- Чтобы остановить задачу, сохраните ссылку на job и вызовите
  `job.schedule_removal()`.

## Обработка ошибок

- Неверный формат даты или дата в прошлом — понятная подсказка, диалог не падает.
- Ошибки БД и отправки сообщений обёрнуты в `try/except` — бот продолжает
  работать, детали пишутся в лог.
- Глобальный `error_handler` ловит необработанные исключения и сообщает
  пользователю, что что-то пошло не так.
- Перед запуском токен проверяется запросом `getMe` (requests); при проблемах
  с сетью бот всё равно пытается стартовать, при неверном токене — останавливается
  с понятным сообщением.
